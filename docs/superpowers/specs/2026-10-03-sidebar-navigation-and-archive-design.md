# 侧边导航、文稿抽屉与归档生命周期设计

## 目标

在现有听道前端中加入一个独立的窄侧边导航栏，并明确三个内容区域：文稿、收藏、归档。

- 文稿、收藏、归档使用小图标入口；图标使用现有主题色令牌，不引入固定品牌色。
- 听道品牌标识继续保留在项目抽屉中，不移动到独立导航栏。
- 项目抽屉只属于“文稿”主界面；进入收藏或归档时，项目抽屉隐藏，内容改由主区域承载。
- 返回主页始终回到“文稿”主界面，并清理当前打开的项目/集合页面状态。
- 普通文稿界面的原“删除”入口改为“归档”；归档项目集中在归档区域管理。
- 真实删除只在归档区域出现，继续复用现有删除确认和回收站流程。
- 抽屉底部工具条作为独立的胶囊控件保留现有控件 ID，启用高斯模糊和最大圆角。

## 状态模型

前端新增一个独立的导航状态：

```text
section = documents | favorites | archive
```

- `documents`：显示既有项目抽屉和文稿主界面；主区域可显示欢迎页或打开的项目。
- `favorites`：隐藏项目抽屉；主区域显示收藏项目列表。归档项目不出现在收藏列表。
- `archive`：隐藏项目抽屉；主区域显示已归档项目列表，同时提供恢复和真正删除。
- 打开任意项目时不改变 `section`，但项目内容覆盖集合列表；顶部返回主页按钮统一调用“回到文稿主界面”。
- 录音/暂停期间维持现有录音状态限制，不允许通过集合入口打断录音流程。

导航栏与项目抽屉是两个兄弟布局区域。抽屉收起时只收起项目抽屉，导航栏仍然存在；因此底部抽屉工具条不再承担主导航职责。

## 项目元数据与 API

在 `session.json` 中增加两个可选布尔字段：

```json
{ "favorite": false, "archived": false }
```

读取旧项目时缺失字段按 `false` 处理。

历史记录 API 为每个项目返回 `favorite` 和 `archived`。新增一个小范围的项目状态更新接口，支持按项目 ID 批量更新 `favorite` 或 `archived`，并返回成功结果。

生命周期规则：

- 文稿列表：`archived === false` 的全部项目。
- 收藏列表：`favorite === true && archived === false` 的项目。
- 归档列表：`archived === true` 的项目。
- 文稿操作“归档”只设置 `archived=true`，不删除项目数据。
- 归档操作“恢复”设置 `archived=false`，项目回到文稿列表；收藏标记保留。
- 归档操作“删除”才调用现有真实删除接口和确认弹窗。

## 视觉与交互

- 独立导航栏保持窄宽度，图标按钮尺寸紧凑，提供 `title` 和可访问名称。
- 当前项使用主题色图标/文字和浅色主题底；非当前项使用现有弱化色。
- 不新增大标题、夸张插画或第二套品牌标识。
- 项目抽屉底部工具条改成靠下的小型胶囊：最大圆角、半透明背景、`backdrop-filter: blur(...)`、细边框和轻阴影。
- 现有排序、导入、录音模式、设置控件保留原 ID 和功能，避免破坏已有快捷键/状态逻辑。

## 验证标准

1. 前端行为测试覆盖导航项、项目过滤、归档/恢复/删除入口和返回文稿主界面。
2. 后端测试覆盖旧项目默认字段、历史记录字段和状态更新接口。
3. 运行现有前端/后端测试，并在实际运行的听道 App 中验证：
   - 文稿页可见项目抽屉，收藏/归档页不可见；
   - 返回按钮从项目、收藏、归档均回到文稿主界面；
   - 普通项目菜单不再出现真实删除，归档页才出现；
   - 归档、恢复、真正删除状态可持久化；
   - 独立导航栏和底部胶囊工具条在主题变化下仍使用主题色。

## 不在本次范围

- 不改变现有项目分组的数据结构和拖拽逻辑。
- 不移动或删除听道品牌标识。
- 不重做文稿正文、播放器或转录内容布局。
- 不把收藏/归档做成新的独立窗口或新的后端存储系统。
