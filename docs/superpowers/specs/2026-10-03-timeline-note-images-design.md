# 时间线便签图文插入设计

## 目标

为“课后时间线便签”纸卡增加本地图文编辑能力：用户可以在光标位置插入一张或多张图片，图片与文字保持插入顺序，后续文字随内容重排；图片可拖拽插入、复制粘贴插入、调整显示尺寸，并通过右键菜单选择首版排版方式。

本设计只覆盖课后时间线便签 `.tn-card`，不改变录音中的快捷笔记 `.notepop`。

## 现状与约束

- 前端便签正文目前是普通 `textarea`，只能保存纯文本。
- 后端项目以会话文件夹为边界，`session.json` 保存结构化数据，`transcript.md` 是可读副本。
- 当前时间线笔记保存、修改、删除接口只处理 `{t, text}`。
- 应用是本地优先产品；图片只保存到当前项目文件夹，不上传云端。
- Tauri macOS 菜单当前没有标准 Edit 菜单，需补齐复制、剪切、粘贴和全选入口；网页自身仍需处理粘贴图片。

## 用户体验

### 插入与编辑

便签正文改为轻量图文编辑器，文字和图片都是可排序内容节点。

- “插入图片”按钮打开系统图片选择器，支持多选。
- 将图片拖入编辑区时，编辑区阻止浏览器默认打开文件，并在目标位置显示一条插入指示线。
- 光标位于文本之间时，图片插入该光标位置；光标不明确时插入正文末尾。
- `Cmd/Ctrl + V` 遇到剪贴板图片时插入图片；普通文本粘贴保留为纯文本，避免外部 HTML 污染便签。
- 图片显示为可选中的独立节点；选中后显示尺寸控制柄，拖动角点按原比例缩放，宽度限制在编辑区可用宽度内。
- 图片节点右键打开排版菜单；删除菜单项只删除当前图片节点，不删除用户原文件。
- 取消或关闭未保存的便签时，已复制到项目目录但未被任何已保存便签引用的图片会被清理。

### 首版排版模式

首版菜单保留参考图的 Word 语义，但只实现可稳定映射到当前编辑器的五种模式：

| 菜单 | 首版行为 |
| --- | --- |
| 嵌入型 | 图片作为行内不可拆分节点，文字继续排在图片前后。 |
| 四周型环绕 | 图片浮动在文字一侧，文字按图片矩形边界环绕。 |
| 上下型环绕 | 图片独占一块内容行，上下文字不进入图片区域。 |
| 衬于文字下方 | 图片作为当前内容区域的底层节点，文字绘制在其上；不提供自由页面定位。 |
| 浮于文字上方 | 图片作为当前内容区域的上层节点，文字绘制在其下；不提供自由页面定位。 |

“紧密型环绕”“穿越型环绕”“编辑环绕边界”“固定在页面上的位置”和“更多布局选项”首版不实现，不显示为可用功能。这样不会制造菜单已经支持但实际行为不一致的假象。

## 数据与文件

每个项目文件夹增加 `note-images/`，图片复制进该目录，使用随机资产 ID 作为文件名，保留安全的原始扩展名。原文件不移动、不覆盖。

新笔记继续保留 `text` 字段作为纯文本投影，兼容现有列表、复制和旧接口；同时增加 `content`：

```json
{
  "t": 842.0,
  "text": "这里的光线和氛围很好，值得参考：\n后续可以尝试其他角度。",
  "content": [
    {"type": "text", "text": "这里的光线和氛围很好，值得参考："},
    {
      "type": "image",
      "id": "a1b2c3...",
      "file": "note-images/a1b2c3.png",
      "name": "IMG_1234.png",
      "mime": "image/png",
      "bytes": 250880,
      "width": 640,
      "height": 480,
      "displayWidth": 260,
      "layout": "inline"
    },
    {"type": "text", "text": "后续可以尝试其他角度。"}
  ]
}
```

旧笔记没有 `content` 时，按现有 `text` 渲染；新笔记始终同时写入 `text` 投影和 `content`。`displayWidth` 使用编辑区像素宽度保存，重新打开时再按编辑区宽度夹紧，避免窗口变窄时溢出。

后端增加受路径校验保护的图片读取路由，只允许读取当前项目 `note-images/` 下已登记或存在的图片文件，并返回对应图片 MIME。`transcript.md` 继续由 `session.json` 重写，图文笔记用相对路径 Markdown 图片链接表达，以便整个项目文件夹拷贝后仍可读。

## 编辑器实现

使用原生 `contenteditable` 和自定义图片节点，不引入富文本编辑器依赖。图片节点使用 `contenteditable="false"`，内部只负责预览、选中、缩放和删除；文字编辑继续由浏览器原生输入法处理。

编辑器需要维护以下状态：当前选中图片、当前 Range 光标、拖拽插入指示器、待保存资产和编辑器是否发生改变。保存前把 DOM 内容规范化为 `content` 节点数组；加载时由 `content` 节点重新生成 DOM，不把用户输入的 HTML 直接当作持久化格式。

图片资产先以预览 URL 显示，保存时通过本地回环 API 写入当前项目的 `note-images/`。后端限制单张图片 20 MiB，超出时拒绝保存并保留编辑器内容，前端给出明确错误。

## 接口与兼容

现有新增、修改、删除时间线笔记接口继续保留路径，但请求体增加 `content` 和待写入图片资产；响应继续返回完整 `notes`，让前端复用现有重渲染流程。

- 新增：校验会话、时间、内容节点和图片资产后写入 `session.json`。
- 修改：以现有索引、时间和文字快照防止并发误改；成功后清理被移除且不再引用的旧图片。
- 删除：删除笔记节点后清理该笔记不再引用的图片，并重写 `transcript.md`。
- 读取：`load()` 对旧纯文本笔记补足默认渲染信息，但不回写旧数据，避免打开历史项目产生无关 diff。
- 复制：现有纯文本复制继续使用 `text` 投影；Markdown 文件保留图片相对链接。

所有图片路径都必须经过会话 ID、文件名和目标目录校验，禁止 `..`、绝对路径和跨项目读取。图片内容只在本地回环服务中处理，不进入转写、摘要或云端接口。

## 壳层剪贴板

macOS Tauri 菜单增加标准 Edit 子菜单，提供 Copy、Cut、Paste、Select All；网页端不拦截编辑器内的这些默认行为，只在识别到剪贴板图片时接管粘贴并转成图片节点。录音快捷键监听继续排除编辑器输入区域，避免抢走 `Cmd/Ctrl + C/V`。

## 测试与验收

增加前端静态/行为测试覆盖：

- 单图、多图、图文混排的序列化与恢复。
- 五种排版模式的 DOM/CSS 语义。
- 选中、删除、角点等比缩放和尺寸边界。
- 文件选择、拖拽指示器、剪贴板图片粘贴。
- 取消清理未引用资产，修改/删除清理旧资产。
- 旧 `{t, text}` 笔记继续可读可编辑。

增加 Python 后端测试覆盖：

- 图片资产保存到当前项目 `note-images/`，不会写入其他项目。
- 非法路径、超限文件、缺失资产和跨项目引用被拒绝。
- 新增/修改/删除笔记后 `session.json` 与 `transcript.md` 一致。
- Markdown 图片链接使用相对路径。

验收不能只依赖静态测试：需要在实际运行的测试 App 中验证文件选择、拖拽、Finder/系统图片复制粘贴、右键菜单、缩放手柄、深色模式和窗口变窄后的排版；同时确认源代码、测试 App 和最终打包资源使用的是同一份 `index.html` 与 `app.py`。

## 非目标

- 不修改录音中快捷笔记。
- 不做自由画布、任意旋转、裁剪、图片滤镜或批量图片管理。
- 不在首版实现紧密/穿越轮廓编辑、固定页面坐标和完整 Word“更多布局选项”。
- 不把图片上传到任何云端服务。
