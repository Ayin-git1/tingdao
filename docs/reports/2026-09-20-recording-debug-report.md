# 听道录音功能调试总结与可复用经验

日期：2026-09-20  
范围：macOS 麦克风录音链路、VPIO 采集、母带写盘、ASR 转码、测试壳部署  
最终状态：已完成；用户在最终版本确认“问题完全解决”。

## 1. 结论先行

本次问题不是单一的“麦克风质量差”，而是多个层次的问题叠加：运行时实际加载了旧的内嵌助手、VPIO 重用缓冲区时错误上报了容量、输入与输出回调职责混用，以及 VPIO 自动增益把底噪和瞬态一起抬高。

最终链路已经收敛为：

```text
VPIO 输入回调
  -> 预分配 AudioBufferList
  -> MicRingBuffer（只写入，不做重采样）
  -> 独立写盘线程
       -> 原生 44.1 kHz 母带 raw-master.s16 -> audio.wav
       -> 独立 16 kHz 分支 -> ASR/VAD -> audio.m4a

VPIO 输出回调 -> 只提供静音
```

已落实的关键约束：

- 回调只负责连续采集并写环形缓冲，不再用 20 ms 轮询驱动 PCM 生产。
- 缓冲不足不补零；写盘线程只消费真实采集到的帧。
- 重采样和写盘在独立线程执行。
- 每次 `AudioUnitRender` 前，`mDataByteSize` 按本次 `inNumberFrames` 设置，而不是使用预分配容量。
- 输入、输出回调按 VPIO 总线职责分开注册。
- 显式关闭 VPIO 自动增益，避免录音电平明显高于系统级软件。
- 测试壳内嵌助手与源码助手同步、签名，并受二进制一致性测试保护。

正式安装版/DMG 未被本次调试改动；验证范围是当前源代码和 `/Users/ayin/Applications/听道-测试版.app` 测试壳。

## 3. 根因、修复与验证

### 3.1 旧的内嵌助手仍在运行

只重建源码目录的 `TingdaoMic.app` 不足以修复测试壳。实际热测试由 `TINGDAO_MIC_APP` 指向测试壳内的：

`/Users/ayin/Applications/听道-测试版.app/Contents/Resources/TingdaoMic.app`

旧副本不认识 `--master-rate-file`，所以出现 `rate.*` 缺失。修复后每次都要同步二进制、重签名内嵌助手和外层测试壳，并用 `cmp`/回归测试确认一致。

### 3.2 `mDataByteSize` 报了容量而不是当前帧数

VPIO 重用预分配的 4096 帧缓冲时，回调实际可能只请求 512 帧。若仍把 `mDataByteSize` 报成 4096 帧，`AudioUnitRender` 会看到错误的有效数据边界，导致 512 帧边界出现约 -7 dBFS 的突变，听感就是高频波动和电流声。

修复为每次 render 前调用 `resetVpioRenderByteSizes(frames)`，使字节数与本次 `inNumberFrames` 一致。这个约束应当作为静态测试保护，而不是依赖听感回归才发现。

### 3.3 输入与输出回调职责混用

VPIO 的输入采集和输出渲染不是同一个职责：

- 输入：`kAudioOutputUnitProperty_SetInputCallback`，element 1；回调中 `AudioUnitRender` 并写入 ring。
- 输出：`kAudioUnitProperty_SetRenderCallback`，element 0；只提供静音。

把输入拉取逻辑塞进输出回调会让回调时序和边界行为变得不可控，尤其容易制造间歇性爆点。之后必须把总线、回调、数据流向画清楚再改代码。

### 3.4 VPIO 自动增益放大了问题

`12:53` 样本没有满幅削波，不能把“听起来很大”直接等同于数字 clipping。VPIO 的自动增益会同时抬高人声、底噪和瞬态，造成与系统级录音软件电平不一致。

最终在初始化前显式设置 `kAUVoiceIOProperty_VoiceProcessingEnableAGC = 0`，母带保留真实电平，再由后续播放/导出策略决定是否需要处理。比较样本时固定使用标准麦克风模式，不要在录音中途切换 `standard` 与 `voiceIsolation`。

## 4. 最终实现约束

### 采集线程

- 预分配渲染缓冲，回调内不动态分配。
- 回调只执行 render、检查错误、写 ring。
- 不做 20 ms 轮询、不做补零、不直接写磁盘。

### 写盘/重采样线程

- 先完整排空 ring，再关闭母带文件。
- 原生采样率母带用于 `audio.wav`，保留麦克风真实细节。
- 16 kHz 分支只服务 ASR/VAD，避免把转写接口误当成母带。
- master 初始化失败时清理所有 scratch 文件，不能留下半成品状态。

### 部署

- 修改助手后同步 `TingdaoMic.app` 的源码副本和测试壳内嵌副本。
- 重新签名内层 helper、内嵌 App 和外层测试 App。
- 不把测试壳的成功误认为正式 DMG 已更新；两条发布边界必须分开验证。

## 5. 可复用排查流程

1. **先确认实际进程路径**：记录 `TINGDAO_MIC_APP`、内嵌 helper 路径和二进制哈希，不能只看当前源码。
2. **先看日志再听感归因**：至少保留 `vpio ok sr`、`preferred`、`active`、`renderErr`、写入/拉取帧数、ring dropped。
3. **确认文件事实**：用 `ffprobe` 检查采样率、声道、时长；用 `volumedetect` 检查平均/峰值；统计满幅样本和异常跳变。
4. **专门检查回调边界**：把异常样本索引映射到回调帧数（本次为 512 帧），优先怀疑字节数声明和 ABL 生命周期。
5. **一次只验证一个假设**：先修部署，再修 buffer 边界，再修回调拓扑，最后处理 AGC；每步都做新样本和日志对照。
6. **做真实录音验收**：静音 probe 只能证明启动、写流和 `renderErr=0`，不能证明音质；最终必须有一段人声样本并由用户确认。
7. **完成前跑全套门禁**：Python 测试、Node 快捷键测试、Swift arm64 编译、`git diff --check`、源码/内嵌 helper `cmp`、`codesign --verify --deep --strict`。

## 6. 错误思考反思

- **把“音量大”先归因于手动增益**：代码中没有简单的乘法增益；峰值数据也证明 `12:53` 不是满幅削波。以后先区分模拟/自动增益、数字削波、底噪抬升和边界跳变。
- **把“源码已重建”当作“运行时已更新”**：桌面应用常有内嵌 helper、缓存和环境变量覆盖。以后先画出实际执行路径，再验证产物哈希。
- **只依赖静态测试、编译和签名**：这些只能证明结构和可执行性，不能证明音频连续性或主观音质。以后把真实人声样本列为完成条件。
- **用临时调大 ABL 字节数“修复” render 错误**：这掩盖了有效帧边界问题，最终制造了更隐蔽的 512 帧跳变。遇到 `AudioUnitRender` 错误必须查清 frame count、byte size 和总线拓扑，不做容量冒充有效数据。
- **把无声、丢帧和静音混为一谈**：应同时看音频样本、ring 计数和 `renderErr`；“样本安静”不等于“采集链路丢失”。
- **忽略系统麦克风模式切换**：`standard` 与 `voiceIsolation` 会改变处理链路。做对比测试时固定模式，避免把模式切换造成的差异误判成代码回归。
